## 快速判断：针对 Clash 的特性
如果点击测速发现所有节点显示 `Timeout`，这明确表示 Clash 核心无法与远端服务器建立基础 TCP 连接。

## 针对 Clash 特性的排查步骤

### 第一步：确认机场端状态
打开浏览器直连访问机场官网：
1. 检查套餐是否有效。
2. 检查流量是否已耗尽触发了断网保护。
3. 查看首页公告，确认是否处于特殊的“防火墙高墙期”。

### 第二步：强制更新 Clash 配置（Profiles）
机场更换了入口节点，而你的 Clash 没有自动同步。
1. 在 Clash 界面进入 **订阅/Profiles** 选项卡。
2. 右键点击你的配置档案，选择 **更新/Update**。
3. **重要提示**：如果更新失败报错，说明你当前网络连不上配置文件的下载地址。请关闭 Clash 的系统代理（System Proxy），或者回官网复制一个“备用 Clash 订阅链接”重新导入。

### 第三步：检查代理模式（Mode）
如果你不小心切错了模式，会导致所有流量不走节点。
- 确保工作模式处于 **Rule（规则）** 或 **Global（全局）**。
- 如果选了 Direct（直连），访问外网会失效。

### 第四步：校准 Windows/Mac 系统时间
- 如果你的电脑时间慢了 5 分钟，底层 Trojan 等协议的防重放攻击机制会让节点 100% 超时。
- 必须进入系统设置，点击“自动同步网络时间”。

### 第五步：TUN 模式虚拟网卡问题
如果你开启了 Clash 的 **TUN 模式（虚拟网卡）**，有时 Windows 的网卡驱动会卡死。
- 尝试关闭 TUN 模式，仅开启 System Proxy 看看是否恢复正常。

### 第六步：避免端口占用与冲突
如果你之前开着 v2rayN，又打开了 Clash，两者可能会争夺 `127.0.0.1:7890` 端口。
- 检查 Clash 的 Logs 页面，如果满屏红色的 `bind: address already in use`，请打开任务管理器彻底结束其他代理进程。
